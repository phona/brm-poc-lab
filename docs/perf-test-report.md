# Warm-Flow 1.3.8 性能与稳定性测试报告

> 测试日期：2026-05-13  
> 引擎版本：`org.dromara.warm:warm-flow-mybatis-plus-sb3-starter:1.3.8`  
> 运行环境：Docker Desktop (macOS) / MySQL 8.4 / Spring Boot 3.2.5 / Java 17  
> 容器资源：JVM 默认堆内存 (~1.9GB) / MySQL 无显式限制 / 无 CPU 限制

---

## 一、测试方法

使用 `curl` + Shell 并发脚本直接压测 Java 引擎 HTTP API（端口 8081），绕过 Go Gateway，排除网络代理层干扰。

测试脚本：`scripts/perf-test-v2.sh`

## 二、测试结果

### 2.1 单线程串行基准

| 场景 | 次数 | 总耗时 | 平均/次 | TPS |
|------|------|--------|---------|-----|
| 启动流程 | 100 | 1606ms | **16ms** | 62.2 |
| 完整流转（启动→审批→结束） | 50 | 5891ms | **117ms** | — |

**结论：** 单次启动约 16ms，完整两节点审批链路约 117ms（含 3 次 HTTP 往返），对于审批类业务完全可接受。

---

### 2.2 并发启动流程（阶梯加压）

| 并发数 | 总请求 | 总耗时 | 平均/次 | TPS |
|--------|--------|--------|---------|-----|
| 10 并发 × 5 轮 | 50 | 1310ms | 26ms | 38.1 |
| 20 并发 × 5 轮 | 100 | 1485ms | 14ms | 67.3 |
| 50 并发 × 5 轮 | 250 | 1788ms | **7ms** | **139.8** |

**结论：** 并发增加时单次耗时反而下降（批处理效应），TPS 线性提升至 ~140。容器无崩溃。

---

### 2.3 极限并发探测

**结论：** 100 并发瞬时启动，平均仅 2ms，容器稳定存活。

### 2.4 会签并发审批 — 锁竞争测试

## 五、已知限制与建议

1. **未测试场景**
   - 500+ 超高并发瞬时冲击（测试 3 中 50 并发 × 5 轮已验证，更高并发需生产环境测试）
   - 长时间（小时级）持续高负载内存变化
   - 数据库慢查询场景（当前无索引优化评估）

2. **生产环境建议**
   - JVM 显式设置 `-Xms512m -Xmx2g`，避免容器 OOM
   - HikariCP 配置 `maximum-pool-size: 20`（当前默认 10）
   - MySQL `flow_instance` / `flow_task` 表按 `create_time` 分区或归档，防止历史数据膨胀
   - 配合 Redis 缓存待办列表，减轻引擎查询压力
